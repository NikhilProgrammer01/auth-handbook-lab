Demo 5 — Stale Proof / Token Revocation

Lesson 1.1 · Bearer Credential
"Whoever holds the card is you (a bearer credential); a lost card must be invalidated (the revocation problem)."
After logout, can the token still be used? The broken logout returns 200 but does nothing server-side — the token remains valid. The secure logout adds the token to a blacklist; the next request with that token gets 401.

Recommended flow: (1) Click broken logout → (2) Click "Check token" → 200 (still alive). Then (3) Reset → (4) Click secure logout → (5) Click "Check token" → 401 (revoked).

Demo 6 — Auditing

Lesson 1.1
"Auditing (Accounting): 'What happened, and who did it?' The record that lets you investigate later."
Every request to /api/* is logged in the terminal where you ran node server.js. Look for lines like these as you interact with the demos above:
[AUDIT] 2026-11-08T10:00:01Z | user=1(user) | GET /orders/101 | ALLOW
[AUDIT] 2026-11-08T10:00:03Z | user=1(user) | GET /orders/102 | DENY(403)
[AUDIT] 2026-11-08T10:00:05Z | ANON | GET /orders/101 | DENY(401)
[AUDIT] 2026-11-08T10:00:07Z | user=1(user) | DELETE /sellers/10 | DENY(403)
[AUDIT] 2026-11-08T10:00:09Z | user=2(admin) | DELETE /sellers/10 | ALLOW
Notice: ALLOW and DENY are recorded with the principal, path, and timestamp. This is how you answer "did user X access resource Y at time Z?" after an incident. Without this, you are flying blind.
